FIRST 90 DAYS · PROPOSED DELIVERY PLAN

Establish ownership. Prove one use case.

A structured sequence: baseline audit, synthetic prototyping, bounded pilot, and a funded scale gate.

Days 1–30

Diagnose & agree

  • Inventory accounts, access, contracts, tags, feeds and conversion definitions.
  • Map agency/market responsibilities and delivery cost baselines.
  • Select one priority banking product, market, channel and permitted outcome.

Output
Baseline audit, risk register, ownership matrix and pilot charter.

Gate: sponsor, data governance, and pilot scope approved.

Days 31–60

Specify & prototype

  • Write event schema contracts, API mappings (Google, Meta, LinkedIn), and NFRs.
  • Test in staging with synthetic data; validate deduplication, retries and exclusions.
  • Set creative metadata taxonomy, QA protocols and incident procedures.

Output
Demonstrable prototype and test evidence against acceptance criteria.

Gate: joint Technology, Data and control-owner review.

Days 61–90

Pilot & decide

  • Run a budget-capped pilot; reconcile events against approved banking outcomes.
  • Check event reconciliation, signal latency, spend control and match rates.
  • Formulate capability transfer playbooks and internal AdOps runbooks.

Output
Pilot readout, operating runbook and funded six-month roadmap.

Gate: expand, refine, or stop based on empirical evidence.

Working sequence; access, staffing and approvals determine release timing. No assumed DBS baseline or promised uplift. 04 / 05
Highlight the disciplined delivery rhythm: Days 1-30 aligns with Technology Risk Management (TRM) and Data Governance Council. Days 31-60 builds the event contracts and tests with synthetic payloads. Days 61-90 runs the bounded live pilot, reconciling media signals directly against core banking records.
